# Tasklane - Implementation Status

Living record of what is built against SPEC section 22, the milestones inside each phase, issues found on the way and
how they were resolved. Updated at the end of every milestone, together with the "Implementation status" table in
TESTPLAN.md, after the suite is green and before the commit and push.

**Working rule.** A milestone is closed only when: its tests are written and pass (`make test`), TESTPLAN.md is updated,
this file is updated, and the work is committed and pushed.

M3.3 gaps: no workflow schemes (a project has one workflow, not one per issue type); agents' automatic claim and release transitions pick a transition by category and do not run conditions, validators or post-functions; the "approval granted" condition and the update-parent, fire-event and run-automation post-functions are not built; rules are edited as JSON lists in a dialog, not as forms; the transition screen is saved as an edit before the transition, not in the same transaction; workflow rules and versions are not in the export and import bundles; the diagram is drawn from the list and cannot be dragged. Issues found: a query ignored inside a transaction (the description lookup) aborted it and showed up as a later "transaction is aborted" error (the failing statement is now checked); publishing a rename onto a name another status was giving up hit the unique index (all live names are parked first); a re-render on blur lost the click on a neighbouring button in the editor (only the transition card is rebuilt now); removing a status whose issues are still being migrated would have orphaned them (refused until the job finishes).

M3.2 gaps: no admin page for screens, schemes, configurations and rules yet (API only); required and hidden are enforced for custom fields and for description, priority, assignee and labels, not for summary; the view operation shapes the form definition but the ticket still shows all fields it can see. Issue found: dialogs had no accessible name (axe `aria-dialog-name`); `modal()` now names each dialog by its heading.

M3.1 gaps: export and import bundles do not yet carry custom fields (EXP round trip), custom-field columns on the board card and list are not shown (`show_on_card` is stored), behavior rules need M3.2. Custom-field queries are always answered by PostgreSQL; the OpenSearch router falls back for them (tested). Issues found: a field-list cache hid new fields from search (cache removed); an unused SQL parameter in a typed clause broke the statement (lazy parameter); a role lookup through the pool inside the create transaction exhausted the connection pool under 25 concurrent creates (hang found by `TestKeysAreUniqueUnderConcurrency`; the role is now read before the transaction); in the UI the ticket re-renders as panels load, so the field definition is cached to avoid replacing a control in use.

## Deviations from the spec (deliberate, to be revisited)

| Area | Spec | Built | Reason |
|---|---|---|---|
| Rich text | ProseMirror JSON canonical (DESIGN Part II) | Plain text with Markdown-style blocks separated by blank lines; merge works per block, then per word | Keeps M1a testable end to end; the merge, `text_seq` and history layers are format-agnostic. The editor schema and converters land with the UI milestone or M3 |
| History | Written asynchronously from the outbox | Written in the same transaction as the change | Removes a class of lost-history bugs (E1 and HIST-06 risk) at no cost on one node. The outbox still carries the events; an async history writer can replace this later |
| Tenancy | Organization root | Single organization | Multi-org is optional in the spec; a migration adds it |
| Presence and change events | WebSocket channel, Redis for 2+ nodes | WebSocket gateway and in-process presence and fan-out (single node); pages fall back to polling the view with `If-None-Match` when the socket is down | Redis fan-out is for the multi-node profile (M4); on one node the semantics are complete |
| Presence (domain) | WebSocket channel | In-process store with a heartbeat API | WebSocket gateway arrives with the UI milestone; the semantics (10 s heartbeat, 30 s expiry, appear-offline) are implemented and tested |

| Malware scanning | Pluggable scanner (ClamAV class), asynchronous `scanning` state | Built-in streaming EICAR signature check at commit, so a blob is `clean` or `blocked` immediately | The `scanning` state, the download refusal and the scan column exist; an external scanner replaces the signature check behind the same call |
| Upload modes | Proxy and direct-to-S3 | Proxy only, `fs` backend | S3 and direct upload are M2 |
